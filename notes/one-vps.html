Everything on one box

sprout planted 2026-06 tended 2026-06 2 min read

One server runs almost everything I've built. A handful of projects, one box, under ten dollars a month.

People assume this needs orchestration. Kubernetes, a CI platform, a container registry, a managed database. It doesn't. It needs a reverse proxy and a habit.

The front door

Every request hits Caddy first. One process, one config file, and it handles TLS certificates for me. No certbot, no renewal cron, no remembering to renew anything. I write down a domain, Caddy gets the cert.

app.example.com {
    reverse_proxy localhost:4000
    encode gzip
}

static.example.com {
    root * /srv/www/site
    file_server
}

That's the whole pattern. Each project listens on a private port. Caddy maps a subdomain to that port. Nothing else on the box is exposed to the internet.

Two ways to run a thing

Every project on the box is one of two shapes.

If it's already containerized, it's a docker-compose.yml in its own folder.

services:
  app:
    build: .
    ports:
      - "3000:3000"
    env_file: [.env]
    volumes:
      - ./data:/app/data
    restart: unless-stopped

If it isn't, it's a systemd unit. Same idea, less Docker.

[Service]
WorkingDirectory=/opt/myapp
ExecStart=/opt/myapp/.venv/bin/uvicorn main:app --port 8000
Restart=always

[Install]
WantedBy=multi-user.target

Both end the same way: a process bound to localhost, restarted on failure, fronted by Caddy. Docker or systemd is just a detail of how the process gets started. The shape of the system doesn't change.

The database is just there

Postgres runs on the box. Not in a container, not managed, not a separate thing I pay for. Apps connect to localhost. Backups are a dump on a timer. For the traffic I have, this is plenty, and it will stay plenty for a long time.

Exposing my laptop

Sometimes I want a public URL pointing at something running on my own machine. A webhook target while developing, a quick demo, a service I don't want to deploy yet.

So the box also runs a small self-hosted tunnel. A subdomain on the server forwards through an SSH reverse tunnel to a port on my laptop. Public HTTPS on one end, localhost on the other. It's ngrok, except I own both ends and it costs nothing.

Deploying is boring

Pull the code, rebuild, restart. git pull && docker compose up -d --build, or git pull && systemctl restart app. No pipeline, no registry, no waiting on a runner somewhere.

Boring is the point. The most exciting thing that should happen during a deploy is nothing.

What I don't run

No Kubernetes. No Terraform. No CI platform billing me by the minute. No service mesh, no load balancer, no autoscaler for traffic that fits in a corner of one CPU.

The box has been up for months, sitting at a third of its disk and a fraction of its memory. When one box isn't enough, I'll get a bigger box. That day is further away than you'd think.
