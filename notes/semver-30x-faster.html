semver, but 30x faster

evergreenDec 20251 min read

Every npm install parses version strings. Thousands of them. Installing preact alone calls semver 21,000 times. One package.

The semver package has 150 million weekly downloads. And it's doing way more work than it needs to.

The dumb idea

Version numbers aren't random. React is at 18. Node is at 22. Most packages never pass major version 50. So I precomputed all of them.

const cache = Object.create(null);
for (let M = 0; M < 50; M++)
  for (let m = 0; m < 50; m++)
    for (let p = 0; p < 20; p++)
      cache[M+'.'+m+'.'+p] = {major: M, minor:m, patch:p};

50,000 objects. Allocated once. Now parsing 1.0.0 is just a hash lookup. No regex. No nothing.

Then compile the ranges

^1.2.3 always means the same thing. So compile it once to a closure:

(M, m, p, pr) => !pr && M === 1 && ((m-2)||(p-3)) >= 0

Next time you check any version against ^1.2.3, it's four integers and some arithmetic. Done.

Result

208 million parses per second. 35x faster. 6.4 kB gzipped. Zero dependencies.

Half my ideas didn't work. Hash arrays were slower than V8's internals. Fast-path parsing added overhead because the cache was already fast enough. Benchmark everything. Your gut is wrong.
