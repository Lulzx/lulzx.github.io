01 / 06

The Pentium 4 and a phone screen

Origin · 2017

I grew up with a very slow Pentium 4 computer. Opening a heavy program meant listening to the fan spin up and watching the cursor stall until the disk finished thrashing. On a machine like that, you learn early that software has weight. Every extra process, every background updater, and every careless megabyte takes time out of your day.

For a stretch after that, I did not have a computer at all. In 2017 I started writing Telegram bots on my phone. The first one replied to messages with random quotes and took about an hour to put together. I deployed it from the phone by SSH-ing into a $5 server and running python bot.py.

When a process died at 3am from a timeout, garbage input, or an out-of-memory crash, I fixed it on the same small screen. That was where I learned to keep the queue, the cache, and the log outside a single run so a restart could pick the work back up without dropping a night of messages.

Later I got a ThinkPad E480 with 4 GB of RAM. Four gigabytes left no room for a heavy desktop operating system, so I moved to Linux out of necessity. If the system ate two gigabytes at idle, I had nothing left for the browser, the editor, and the code I was trying to run.

That constraint pushed me through different Linux distributions and deep into how the operating system was put together. I stripped out services I did not need, watched memory numbers in a terminal, and switched to a tiling window manager.

A tiling desktop gives every window a slice of the screen instead of letting them stack into a pile. One pane held the file I was editing, one held the test output, and one held my notes. If a change could not fit in that layout, I was holding two jobs at once. Living inside 4 GB taught me to check what a tool costs before inviting it onto the machine.

03 / 06

Search, distribution, and the wrapper detour

2018 to 2024

With a working Linux setup and a $5 VPS, I spent the next few years building things a single person could run end to end. In 2018 I rewrote my Python bots in Node.js and learned the hard way what nested callbacks do to a codebase. Between 2019 and 2020 I got pulled into information retrieval: indexing Telegram archives in discover, building a quiet book search interface in shoten, and experimenting with vectors, embeddings, and HNSW nearest-neighbor search in sentence-similarity-search before the rest of the industry started calling all of that work AI. Alongside the search tools, I built automated Telegram deal and price-tracking pipelines that had to stay up under real traffic. In 2021 I burned out, wrote nothing for three months, and came back clearer.

In 2023 I picked up Rust to rewrite my command-line tools. The compiler forced me to name the owner, the error, and the lifetime before the first happy path would build. In 2024 I tested the standard startup and agency playbook: Nuxt and Vercel AI wrappers, content-repurposing pipelines, autonomous agent templates, DeFi liquidation bots, and smart-contract bug bounties with immunefi-cli. That stretch taught me what I actually cared about. Gluing heavy JavaScript stacks onto remote APIs felt fragile and hollow. By contrast, finding a real replay bug in a protocol or keeping a bot alive at 3am rewarded reading the raw source and verifying every invariant from first principles.

05 / 06

Refusing hardware ceilings

Apple Silicon & WebGPU

In 2024 I moved my daily work onto Apple Silicon. On my old setups, every GPU workload paid a copy tax across the bus. Unified memory meant the CPU and GPU shared one pool of RAM, so a 14-inch laptop could hold weights and run passes that used to require a remote server.

The reflex from the 4 GB ThinkPad came right back: make the local machine do what people assume needs a cluster. I built a CUDA compiler and runtime for Apple Silicon GPUs in cuda-metal, emulated double-precision arithmetic on Metal GPUs that lack hardware FP64 in VF64-metal, and brought scientific solvers like GROMACS (gromacs-metal), WarpX plasma simulations (warpx-metal), PeleLMeX combustion (pele-metal), and Box3D physics (box3d-metal) onto the M-series GPU.

For language and speech models, I wrote fused Metal kernels in Zig with no Python or PyTorch (tiny-kernel), ran a 2-bit 27B model locally at 20 tokens per second (bonsai-mlx), and pushed full speech recognition (phonon-web) and language models (barunlm-35m-browser) entirely into the browser over WebGPU and WebAssembly.

06 / 06

Where the work is going now

Current Direction · 3 Threads

After rebuilding compilers, virtual machines, and GPU kernels from scratch, the questions I care about shifted. Three threads run through almost everything I am building now.

06.A / Compression & Proof0 LLM calls at check

Learning as Compression & Proof

Scaling a transformer is expensive, and an unverified model will cheerfully invent a plausible lie. I am building MDL learners with no transformer or backprop (solon), zero-token program synthesizers (supsearch, ontogenesis), RL environments scored by a proof checker (gavel), a post-quantum RV64I zkVM (open-magnetar), and an incremental compiler for evidence-backed docs (claim-wire).

Deterministic Boundaries

When orchestrating parallel coding agents (helium, carry-terminal, mimo-build), sandboxing dependencies (caplock), or reconciling infrastructure (alchemy-celld), the 2017 phone-bot rule holds: deterministic code owns the log (memo), grammar (typed-inference), and custody.

I opened this repository in September 2017 with the description "My website to tell my story." The machines got faster and the problems moved from quote bots on a phone screen to compilers, GPU kernels, and whole-brain connectomes, but the bias never changed: keep the footprint small, read the source, and own the stack from the bytes up.
